# meeting-organizer-bot · showcase

Showcase-репозиторий с архитектурными решениями из production Telegram-бота для саппорт-команды. Полный код проекта живёт в приватном репо; здесь — самые интересные модули.

## Что бот делает (в production)

- Грузит встречи из CalDAV-календаря, шлёт карточки в Telegram-чат
- Следит за лимитом одновременных встреч (если >N в одном временном слоте — алертит организатора)
- Кнопки «Взять / Отказаться» для назначения инженера-ведущего, с защитой от гонок
- Самостоятельная привязка сотрудников через `/start <email>` (с проверкой роли по HR-системе)
- Утренний дайджест в 07:00 МСК, напоминания за 10 мин и в 10:50, мониторинг новых/перенесённых/отменённых встреч
- Статистика и отчёты по периодам, графики

## Стек

`Python 3.11` · `aiogram 3.13` · `SQLAlchemy 2.0` · `PostgreSQL 15` · `Alembic` · `APScheduler` · `Docker Compose`

## Что в этом репо

| Модуль | Что показывает |
|---|---|
| `bot/services/capacity.py` | Алгоритм подсчёта пересекающихся встреч за O(N²), ранжирование, явный список изменений для алертов |
| `bot/services/employee_sync.py` | Синхронизация с HR-системой: дедупликация по email с приоритетом активных, мердж дубликатов, выявление ролей по принадлежности к отделу |
| `bot/handlers/callbacks.py` | Двухкликовое подтверждение для рискованных действий, SELECT FOR UPDATE для защиты от гонок, разделение compact / full UI |
| `bot/callback_map.py` | Маппинг длинных event_id ↔ short_id для обхода 64-байтного лимита Telegram callback_data |
| `bot/common_helpers.py` | Текст карточки встречи с pluggable секциями (организатор, лимит, день-в-день, тех.встреча, пересечение с планёркой) |
| `bot/models/` | SQLAlchemy ORM с правильно настроенными partial-индексами, миграции Alembic |
| `docker-compose.yml` | Production-ready setup с healthcheck, volumes для секретов и бэкапов |

## Архитектурные решения, на которые стоит обратить внимание

### Идемпотентность утреннего дайджеста

`bot_state` — KV-таблица для флагов «эта операция уже выполнена сегодня». При рестарте контейнера в 07:01 бот не дублирует утренний дайджест, потому что видит ключ `morning_digest_sent_<date>`. Простая защита от двойной отправки без сложных state-машин.

### Очистка призраков

Когда встречу удаляют в календаре, бот узнаёт об этом не сразу. В `check_for_updates` (каждые 2 мин) и в утреннем дайджесте — отдельный проход: «есть ли в БД встречи на сегодня которых нет в свежей выгрузке CalDAV? Помечаем was_canceled=true». Без этого `capacity_rank` мог бы считать удалённые встречи и слать ложные алерты.

### Двухкликовое подтверждение

Часть встреч помечается как «сверх лимита» — их брать инженеру не рекомендуется. Если он всё же жмёт «Взять», первый клик показывает alert-попап с предупреждением, и **меняет кнопку на «⚠ Всё равно взять»**. Второй клик уже берёт. Реализовано через `edit_reply_markup` + `force_confirm=True` без stateful FSM.

### Short ID map для callback_data

CalDAV event_id длиной 70+ символов не помещается в 64-байтный лимит Telegram `callback_data`. Решение — таблица `short_id_map` с инкрементальным коротким ID. Каждая новая карточка генерирует свой short_id, маппинг хранится в БД (а не in-memory) чтобы выдерживать рестарты.

### Контекстное определение «настоящего» организатора

В mail.ru CalDAV свойство `ORGANIZER` всегда указывает на владельца shared-календаря (например, `support@example.com`), а не на того, кто реально создал встречу. Решение — искать первого `ATTENDEE` с `PARTSTAT=ACCEPTED` из корпоративного домена, исключая известных «фейковых» организаторов.

## Установка (если хочется потрогать)

Этот код — фрагменты, не готовый к запуску проект. Чтобы запустить — нужно склеить недостающую бизнес-логику и заполнить `.env.example`.

```bash
git clone https://github.com/<user>/meeting-organizer-bot-showcase.git
cd meeting-organizer-bot-showcase
cp .env.example .env
# заполнить .env своими значениями
docker compose up -d
```
